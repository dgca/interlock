# Current scope

## Implemented

- Owned child workflow authoring with a Child workflows tab, contextual creation, owner navigation, and explicit child-version selection.
- Public MIT-licensed `@type_of/interlock` npm package with an `interlock` command for the local engine and built UI.
- Dark UI with workflow search, create, clone, rename, archive, restore, import, export, and confirmed deletion.
- Bookmarkable workflow and run URLs, Runs tab persistence, and browser Back/Forward navigation with unsaved-edit protection.
- React Flow authoring and editable raw JSON, with separate draft and publication validation.
- Size-aware node placement and an undoable Tidy action for the whole graph, including nested Batches.
- Session-local Undo and Redo for up to 50 editor actions, including grouped moves and Batch deletion.
- Node creation with an in-dialog type selector and JSON contract editing.
- JavaScript and Bash script nodes, syntax highlighting, aligned line numbers, and top-level JavaScript `await`.
- Editable drafts, immutable published versions, and stale-draft protection.
- Opt-in cascade publication through CLI and MCP to advance and republish transitive dependents atomically.
- Entry, Exit, Agent, Script, Fetch, Wait, Condition, Workflow, and Batch nodes with visible item paths.
- Persisted Wait deadlines and optional unclaimed Agent timeouts with a Timeout route.
- Persistent runs, event history, nested run inspection, cancellation, and explicit retry.
- Global and workflow-specific Runs views with Active and History tabs, live step states, and individual Batch item inspection.
- Workflow Editor and Runs subnav, a settings and deletion menu, and explicit Save and Discard actions in Raw.
- Work requests, capability checks, expiring claims, lease renewal, schema validation, and duplicate submission protection.
- Concurrent child dispatch with ordered collection and explicit failure policy.
- UI-started runs, copyable agent handoffs, and manual completion of unrestricted current-context assignments.
- HTTP MCP on the running server for authoring and execution, with a legacy stdio bridge and CLI access to the same service.
- Example protocol research and opportunity synthesis definitions.
- Changesets versioning and changelogs for the public root package, with synchronized CLI, UI, and MCP versions.

## Current limits

Child ownership has one level. Only the owning workflow can reference its children. Moves, main-library child search, and parent clone/export/deletion with children are not implemented; these lifecycle operations must be completed before releasing the feature. Parent clone and UI export are disabled when children exist, and parent deletion reports a blocking error. Existing workflows are not automatically reorganized.

Agent execution requires a connected harness or manual submission. Interlock does not launch fresh agent sessions or provide direct model API execution. HTTP client configuration is provided for Codex, Claude Code, and OpenCode, plus generic Streamable HTTP instructions. Claude Desktop configuration uses the retained stdio fallback. HTTP MCP has no transport sessions or standalone SSE notification stream. Automated tests verify the MCP transport and packed installation; they do not establish compatibility with every client version or approval policy.

Tool and skill requirements are names checked against executor declarations. The executor supplies their implementations. Interlock does not load arbitrary skill files or manage outgoing MCP connections itself.

Input and output contracts have a field editor with named fields, display labels, required flags, descriptions, nested objects and lists, and text choices. Pasting example JSON generates a draft contract and highlights assumptions to review. Advanced JSON Schema remains available; schemas outside the visual editor’s supported subset stay intact in advanced mode. The run dialog provides fields for common object schemas and JSON editing for complex values. There is no static proof that every connected node's contracts are compatible. Actual inputs and outputs are checked at execution time.

Results are JSON stored in SQLite. The UI exports run records and workflow definitions. Separate artifact storage, rendered recommendation documents, version diffs, and replay against captured sources are not implemented.

Batches support at most 200 items, 50 concurrent item runs, and 10 nested workflow levels shared with Workflow nodes. Each item path stays inside an explicit Batch group on the main canvas. Every item branch must connect to its group's End handle. Output emits the ordered results only after collection finishes. Cycles within item paths and arbitrary parallel graph joins are not supported.

Self-improvement proposals, evaluations, automatic promotion, direct provider adapters, sandboxed script execution, recurring run scheduling, and multi-user access remain future work.

Fetch nodes support HTTP/HTTPS requests, typed input bindings, JSON bodies, response inspection, and explicit retry. Responses are limited to 5 MiB and requests to 120 seconds. Streaming outputs, binary downloads, OAuth configuration, and multipart forms are outside the current scope.

Wait durations and unclaimed Agent timeouts support up to 365 days. Timestamp waits require an ISO timestamp with a timezone. Timers advance on engine checks, normally once per second, and resume overdue deadlines after restart. Claimed assignments have renewable leases but no total execution deadline.
