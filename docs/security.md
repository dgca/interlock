# Security

Interlock is a trusted local tool for one person. Workflows run Scripts, Fetch requests and agents with your user account's access, so treat a workflow like code you run.

- The server listens only on `127.0.0.1`, and the listen address is not configurable. It rejects requests addressed to another host or sent from an untrusted browser origin. Do not expose the port through a tunnel, proxy, port forward or container port mapping.
- Interlock creates a per-install [API token](connect-harness.md#api-token) in an owner-only `api-token` file. The UI, the `interlock` CLI and the stdio bridge send it automatically, and **Connect with MCP** includes it in HTTP client configuration. On loopback the token is optional in 0.2. Set `INTERLOCK_REQUIRE_TOKEN=1` before starting Interlock to reject `/api`, `/trpc`, `/mcp` and `/events` requests without it.
- Scripts are not sandboxed. A Script's [server environment](architecture.md#scripts-and-interruptions) mode decides which of Interlock's environment variables it receives. `minimal` passes only `PATH`, `HOME`, locale variables, `INTERLOCK_*` variables, bound saved variables, execution context and the names you list to pass through. Scripts and polling checks added in the editor start in `minimal`. A Script without a mode, or set to `inherit`, receives the whole server environment, including any credentials in it, so existing and imported workflows keep their behavior.
- Managed agents run at **Default agent permissions** (AI Settings → Execution settings) unless a harness or workflow sets its own level. While no default is chosen, that level is **Full access**. **Full access** removes the harness sandbox and approval prompts: agents run commands and edit files with your account's access without asking. Choose it only for repositories and workflows you trust. See [permission levels](managed-executors.md#choose-permissions).
- Imported Scripts wait for [one-time approval](reuse-work.md#approve-imported-scripts) before their first run. Scripts you write, or that a connected agent writes over MCP, run without approval unless you extend approval to agent-authored Scripts. Review imported Scripts before you run them. Import review also shows each imported workflow's agent permission level; a workflow that sets none runs its managed Agents at your default, which is Full access until you choose one.
- Managed Claude Code sessions load your user, project and local Claude Code settings, including the MCP servers configured there. If Interlock is connected to Claude Code, a managed session can use every Interlock MCP tool that connection exposes. Pi sessions likewise keep their own MCP connections and extensions.
- Claude Code, Codex and Pi sessions that Interlock launches get two tools of Interlock's own: `save_memory_note` and `call_workflow_tool` (see [memory](memory.md#managed-sessions-save-notes) and [agent tools](agent-tools.md#managed-sessions)). Interlock runs each call itself against the claim it holds for the session. The session, its hooks, other MCP servers and the commands it runs never receive a claim token or other credential, in the prompt, the environment or the transcript. Saving is write-only and limited to the session's step and workflow. The tools are off at **Read only**, and run without an approval prompt at **Standard** and **Full access**. In Pi the call travels to Interlock as an extension dialog with a private name; other installed Pi extensions run in the same process and are trusted like any code you install.
- On loopback, while the API token is optional (the 0.2 default), any program on this machine that can reach the server can call the whole API. That includes a managed session that can run commands, or that has Interlock's MCP server configured: it can, for example, approve its own pending memory notes through `memory manage`. The `interlock` CLI also reads the API token file, so a session that can run it has the same access even when the token is required. Set `INTERLOCK_REQUIRE_TOKEN=1` to stop programs that cannot read the token file, and run untrusted workflows at **Read only**.
