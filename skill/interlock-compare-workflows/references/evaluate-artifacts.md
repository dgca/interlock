# Evaluate comparison artifacts

Use the **Evaluate workflow comparison** starter when structural checks alone cannot answer the quality question. For example, two outputs can both pass a check for `selfReport: true` while only one gives the correct answer. Grade the answer or exact artifact revision using the same rubric for both sides.

## Prepare and run an evaluation

1. Read the retained comparison and its captured cases. Decide on the rubric, required checks, and output path before opening either side's artifacts. Use a representative set with comparable case and repetition pairs. Choose `review` for semantic judgments or `checks_only` to record existing structural evidence. Keep the choice visible when reporting results.
2. Use a known published copy of the starter. If needed, use the starter picker or discover it through `list_workflows` with `source: "starters"`. Import only an authorized copy and reuse known copies when possible. For a new authorized evaluation, use `start_run` with the evaluator's exact version, a stable request ID, and input containing the `comparisonId`, `rubric`, `mode`, `outputPath`, and `maxSamples` for the review. If an evaluation run already exists, resume it by run ID. [Evaluator input and setup](https://github.com/dgca/interlock/blob/main/docs/workflow-evaluation.md#capture-a-fixed-evaluation-request)
3. For semantic review, use fresh reviewers who have not seen the trials or each other's grades. Have them inspect the actual output or exact referenced artifact. Read the selected trial output with `get_run_result` and `includeHash: true` for the starter's evidence receipt. Mark inaccessible or unverifiable evidence unknown. The result digest identifies the selected JSON. A file reference inside that JSON still needs independent inspection. [Artifact selectors and evidence](https://github.com/dgca/interlock/blob/main/docs/workflow-evaluation.md#review-actual-artifacts)
4. Follow the starter's recording assignment to write each accepted grade once. Reuse its `EVALUATION_RUN_ID:SAMPLE_ID` request key after uncertain delivery and preserve independent judgments. Pair grades from matching evaluation specifications. Keep skipped, failed, checks-only, and unknown assessments visible, including original samples whose evidence a retry can no longer establish. [Judgment recording](https://github.com/dgca/interlock/blob/main/docs/workflow-evaluation.md#resume-and-record-each-grade-once)

## Interpret the result

- Before relying on agent grades, have a human independently assess a known good artifact, a known failure, and evidence that cannot be verified. Compare criterion findings and supporting evidence. If the rubric changes, record a new evaluation and retain the earlier grades.
- Report coverage and criterion-level findings separately from trial execution and structural checks. An unknown grade can carry a placeholder score of zero. Treat it as unassessed. A checks-only pass supports the structural checks only.
- Read evaluator usage separately with `get_run_usage` and `includeDescendants: true`. Include the preparation, review, and recording work. Keep incomplete usage unknown and avoid averaging unrelated rubrics. Use the combined evidence to advise on adoption. [Evaluator usage and calibration](https://github.com/dgca/interlock/blob/main/docs/workflow-evaluation.md#calibrate-before-relying-on-agent-scores)
