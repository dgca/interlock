Keep checks independent of execution and quality judgment. Add bounded persisted document readers without changing existing records or the database schema.

Advance scheduling under per-comparison and global limits, accounting for all active descendants. Propagate optional comparison metadata and captures through child/Batch creation. Keep ordinary run behavior unchanged. Extend cleanup/deletion guards for queued pins and remove local suite/comparison documents during guarded workflow deletion.

Audit related start/claim/retry/briefing/results, cleanup/deletion, prompt editing and transfer guidance. Existing bundles exclude local experiments.
4. AC10: reuse RunList and RunInspector context areas for comparison/case/side/repetition labels and counterpart navigation. Add a shared concise label component if it avoids divergent formatting. Keep metadata optional, labels wrapping and ordinary runs unchanged. Add focused rendering/navigation assertions. Save screenshots and observed steps outside checkout.

Direct negative/control pairs cover stale suite and preview, idempotency conflicts, malformed/missing checkpoints and paths, mismatched contracts, mutable prompt edits during queued/nested execution, active pin cleanup, detached completion/cancellation, late injected writes, missing source/history, explicit retry observation snapshots and restart without duplicate dispatch. Verify a previous-release fixture opens unchanged and executes prior pins.

Logs/proof remain outside checkout and identify the candidate commit. Update CONTEXT terms, README, architecture, scope, harness/agent instructions, CLI help where affected and pending patch changeset. No schema conversion is planned because new collections and optional fields use compatible readers.
7. SDLC fresh-context review owns independent full diff/spec/standards review plus targeted stale-confirmation, capture consistency, restart/duplicate, detached and cleanup boundary experiments with valid controls. Review compares complete protected state on injected failure. preparePr owns final candidate integrity and the separate #76 PR; no merge or publication.

The highest risks are starting work before a failed transaction commits, losing a queued dependency, prompt drift between samples, and releasing a concurrency slot while detached work remains active. Scheduling must commit run identity before external jobs start, guard pending pins, propagate captured prompts and count the full execution tree. Direct checks above must reach each boundary rather than merely reject malformed input.

The repository already scans small local document collections and exposes ordinary runs through one engine. This plan extends that existing model within explicit bounds; it does not claim distributed scheduling or side-effect-free execution. No unresolved plan decisions remain.
