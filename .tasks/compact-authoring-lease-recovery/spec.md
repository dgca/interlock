# Behavior and acceptance criteria

Scope and authorization are in [intent.md](intent.md).

- **AC1:** MCP create, update, and publish accept `detail: "summary"` and return `ok`, `id`, `draftRevision`, `latestVersion`, `draftMatchesLatest`, and `archived`. Summary publication reflects the committed version, including cascade publication. Omitted detail and `full` preserve full responses. Archive and restore use update. Imports retain their existing compact response.
- **AC2:** `edit_workflow` accepts `diagnostics: "summary"`; omission and `all` preserve full diagnostics. Whole-graph validation and atomic edits remain authoritative. Summary includes all errors and all new or changed warnings, plus at most five samples of unchanged warnings. Metadata reports exact deduplicated totals, returned and omitted counts, and counts by severity and code. Diagnostic identity preserves node, edge, field path, message, and severity; array index changes alone do not make a stable node's warning new. `validate_workflow` remains full preflight. Stale and invalid edits cannot mutate state.
- **AC3:** HTTP and stdio discover object-root output schemas for create, update, publish, edit, and claim, covering full and compact responses. Existing execution schemas remain intact. Invalid modes reject before mutation. Tool descriptions explain the default and the explicit compact option without assuming historical knowledge.
- **AC4:** CLI start and submit accept `--summary`, use the shared continuation API, and include the same suggested read-only next call as MCP. Existing positional version and JSON/file arguments continue to work. Claim accepts `--fresh` and `--lease <seconds>` alongside options JSON; explicit flags override the corresponding JSON options. Unknown flags and invalid durations fail. Omitted flags preserve behavior. A fresh-context assertion remains the caller's responsibility.
- **AC5:** Agent nodes optionally configure integer `maxLeaseExpiries` from 1 through 10. When present, explicit failures exhaust `maxAttempts`, and expiries independently exhaust `maxLeaseExpiries`. Exhaustion occurs on the configured count, with a distinct expiry-budget error. Every successful claim increments `attempt`; it never decreases. Persist `failureCount` and `leaseExpiryCount` for the separate policy and expose them in claim, discovery, and continuation metadata. When absent, retain the combined attempt budget. Capture policy from the published definition when work is created; draft edits and restarts cannot alter it.
- **AC6:** Expired submit and renewal fail with actionable current-state guidance: available to reclaim, superseded by another claim, terminal assignment/run, or exhausted budget. Unknown tokens retain an invalid-token error. Recognized expired tokens stay rejected even after later claims expire. Report actual expiry time, claim count, and separate budgets without calling the claim count a failure-budget fraction. Available is an observation, not a reservation. Expiry processing persists even when the caller receives an error. Completed identical submission remains idempotent. No expired renewal, late-result acceptance, or automatic replay of external effects.
- **AC7:** The Agent editor has an optional separate-expiry-budget switch adjacent to attempts, with an integer input shown when enabled. Enabling starts at 3; disabling removes the setting. Attempt/failure labels and canvas summaries match the configured policy. Reuse existing controls and dialog save/cancel behavior, keyboard navigation, responsive stacking, and definition validation. Applying then saving and reopening retains the value. Invalid values cannot be saved.
- **AC8:** Document the authoring modes, complete CLI execution loop, independent budget semantics, and reclaim recovery, including preserving external work and checking for repeated side effects. Include a pending root patch changeset. Preserve legacy Bash and existing full-response consumers.

## Design choices and limits

Use separate summary API operations for authoring, as execution already does, to keep full API return types stable. Summaries omit definitions rather than truncate them. Counts do not bound arbitrary diagnostic text or the number of new warnings and errors; document this limit.

Compare warnings before and after the atomic edit. Normalize node/edge array indexes using stable IDs, preserving the remainder of each path. Exact duplicate warnings may be removed only in summary mode.

Retain bounded hashed expiry-token receipts with expiry timestamps and claim numbers for diagnostics. Receipts never authorize work and are excluded from external work responses. Existing records without receipts cannot positively identify an old token. The configured finite budgets bound new receipts. Cancellation and unclaimed timeouts take precedence over reclaim guidance.

No unresolved product questions. The selected bounds and optional-control default are routine implementation choices within the accepted bounded-budget design.
