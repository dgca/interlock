# Run projection behavior

Scope and authorization are in [intent.md](intent.md).

- AC1: Every node supports optional trimmed `stage`, 1–200 characters. The node settings Work section provides a Stage text field after Name. Blank removes the stage. Applying and reopening preserves it, and Raw and Visual round trips preserve it.
- AC2: `externalTask.title` is optional trimmed text, 1–200 characters. It participates in idempotent start identity and survives continuation and inspection like the existing URL. Identity filtering remains system plus id.
- AC3: Run lists, full inspection including descendants, briefings including descendant summaries, compact mutation summaries, and newly recorded event payloads expose `stage`, `waiting`, and `actor`. Missing stage or waiting is explicit null. Old events remain valid and are not rewritten.
- AC4: Stage is the deepest active labeled node in the requested run and its active waited descendants, including Batch items. Detached children, terminal children, and earlier completed visits do not override it. Unlabeled children fall back to labeled active ancestors. Equal depth uses latest execution start, then ascending run id and node id. Terminal runs have no active stage.
- AC5: Waiting is null for executing work, or `{kind, detail, since}`. Current mapping covers unclaimed connected Agents (`claim_queue`), managed dispatch (`managed_launch`), explicit managed requests/recovery (`human_request`), External input (`input_node`), external holds (`hold`), claim budgets (`budget`), claim resources (`resource`), timed Wait (`timer`), and polling Wait (`poll`). `detail` contains bounded identifiers and diagnostics, including bounded last-check JSON text for polls with a truncation marker. `pause` and `admission_queue` are reserved contract kinds and are not emitted before those features exist.
- AC6: Actor is agent for connected available/claimed work and external-input callers, engine for deterministic execution, managed dispatch/work, timers, polls, and resources with live owners. Explicit human requests, model/recovery intervention, holds, budget gates, and uncertain resource ownership require person. External input does not establish a human requirement because integrations can submit and accept automatically. Person is selected only when all active leaf branches require it. Progress-capable branches take precedence, then agent over engine, then the stage tie order. Waiting is chosen from that same branch. Terminal runs use engine and null waiting. `since` comes from persisted execution/work/hold times, never the read clock, and stays unchanged across repeated reads and restart absent a state transition.
- AC7: The run inspector and Runs rows show the shared stage and waiting/actor projection using existing text and status components. Legacy `waitReason` remains for compatibility. Names, navigation, and existing recovery controls remain the context; no duplicated subtitles are added.
- AC8: Required docs and affected MCP definitions describe these fields and their limits consistently. HTTP and stdio discovery expose the title bound, node stage and compact-summary contracts. No new MCP tools are needed.

The UI adds one optional text field to the existing node settings form. It uses the existing apply/cancel flow, keyboard order, validation feedback, and responsive layout. Run projection text wraps in existing summary areas. Absent stage adds no empty badge. Loading and error behavior uses the existing queries and notifications.

Technical decisions follow the issue's autonomous authorization. Deterministic single-value projection deliberately reports one branch; existing briefing lists retain the other blockers. No unresolved product questions remain.
