# Declared context continuity

Issue #135. Add optional `context.continuityGroup` to Agent nodes. A group is keyed by the exact run ID and name. Repeated visits and phases within that run share a binding; every child invocation, Batch item, detached run, and separate root run has independent groups. Definitions without groups retain current behavior. A fresh-context Agent cannot declare a continuity group; drafts remain saveable, but publication rejects that contradiction.

Grouped claims require an opaque `{executorId, sessionId}` declaration. The first successful claim binds the group inside the claim transaction; later claims must match both fields. Failed claims do not bind a group. Assignment discovery and briefings expose the expected session and binding revision, without adding history to every response. Claimed/completed work retains the binding used for its attempt. Interlock checks declarations; the external harness creates, resumes, and isolates actual sessions.

A revision-checked handoff changes the binding and records the previous/new session, declared actor, reason, and checkpoint reference. No handoff is allowed while the group has an active claim. Expired work first follows existing lease recovery, and ordinary retry/cancellation rules still apply. The checkpoint is an opaque reference, never read or executed by the server. A retry of the latest identical handoff is a no-op; conflicting or stale revisions reject. Handoffs neither claim work nor reset budgets, counters, or leases.

Persist group bindings and immutable claim/handoff events in additive document collections. Read paginated history on demand, preserve it across restart, and delete it with run history. Update available assignment projections and continuation cursors when the binding changes, so coordinators know the next session. Expose shared API, MCP, and CLI operations, plus group editing and a manual-claim explanation in the existing UI. Manual completion cannot attest an external executor session.

Verify publication versus draft behavior, import/export, same-session continuation across phases/loops/retries, conflicting declarations and atomic claims, handoff idempotency and active-claim protection, restart, independent child/Batch/root groups, fresh reviewer isolation, bounded history, CLI/API/MCP parity, and existing no-group behavior. Use deterministic tests and temporary databases, with no paid model calls.
