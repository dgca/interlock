# Implement background Script recovery

[Spec](spec.md) owns AC1–AC7. [Intent](intent.md) records the original baseline and authorization.

1. AC1/AC3/AC6: add the Script executionMode schema, persisted background metadata, and bounded inspect/stop/reconcile request contract in core. Keep polling checks unchanged. Add a small editor switch and inspect existing run detail presentation.
2. AC2/AC3/AC5: storage owns an owner-only spool beside the file-backed database. Encrypt transient progress and terminal receipts with a per-execution key protected by the existing vault. Persist a launch-intent metadata record before spawn. Send command/input/environment/key through stdin to an independent supervisor, never argv or persistent launch configuration. The supervisor writes an authenticated identity receipt before spawning the actual Script. It checks a durable stop request, enforces the absolute deadline, and atomically writes encrypted bounded progress and result receipts. Record OS start identity with PID and token; never reuse an unproven launch intent.
3. AC2–AC5: runtime launches or reconnects and polls receipts. Keep acceptance in the existing guarded operation settlement transaction. Graceful server stop disconnects monitors without cancelling supervisors. Run cancellation records a stop request only after identity verification. Missing outcome plus missing/mismatched live identity fails uncertain, bypassing failure routes; explicit stopped confirmation clears the replay guard. Run retries remain explicit.
4. AC5/AC6: share the operational method through server/client, grouped MCP tool and CLI JSON command; update related get/cancel/retry guidance without broad discovery text. Progress is decrypted and redacted before returning or persisting metadata, including complete buffered secret matching before tail slicing.

Review affected authoring/run-inspection/cancellation/retry MCP flows and transport discovery tests. Run focused tests, pnpm build, pnpm test, pnpm test:package and pnpm format:check. Capture concise commands/results here or in verification.md. Fetch origin main and rebase before final verification and independent review.

Highest risks and direct checks: a crash between intent persistence and spawn must remain uncertain, never start on restart. Offline completion before reconnect must accept once with one side-effect marker. PID reuse must reject signalling while a valid identity control stops its group. Secret split across log writes must be masked before trimming. A cancelled run must never accept a late outcome. Receipt corruption must fail closed with no raw values in errors. Package smoke must exercise the inline supervisor in the bundled executable.

Build owns all automated checks and representative UI journey. Independent review owns the complete candidate diff, execution/identity/deadline/secret boundary checks and spec conformance. Delivery belongs to preparePr and requires coordinator resume. No final reviewer claim from this author.
