# GitHub folder import

## Accepted behavior

Add public GitHub folder import to the workflow library. Preserve the existing local-file import path for legacy single-workflow documents and portable bundles. Work only in this disposable checkout and temporary databases. Keep commits local.

Support direct files in public `github.com` repository folder links using a commit or branch, including branches with slashes. Resolve a branch to a commit for discovery and import. Do not crawl nested folders. Do not add authentication, automatic updates, a gallery, or a new format.

Each selectable portable file represents its root workflow and includes its workflow and saved-prompt dependencies. Start every preview with no selection. Loading and selecting save nothing. Only the explicit Import action commits the selected files. Validate the entire selection against current local state and commit all changes together. Reject divergent drafts, metadata, published versions, ownership, or shared prompts. No replacement option belongs in this dialog. Identical portable reimports remain no-ops. Each legacy import creates a new workflow. Import never starts a run or executes scripts.

Preserve draft-save and publication validation rules. Incomplete drafts that existing import accepts must remain importable. Published versions still require full publication and reference validation. Invalid JSON, unsupported definitions, unrelated documents, and bundles with missing dependencies must not become valid choices or block valid files.

## Design decisions

The existing library uses the shared dark Mantine theme, compact buttons, card lists, and action feedback. Keep those controls, colors, typography, and spacing. Add no new visual system. The inspected baseline is commit `95cb57b8f9b55e63428f66f0099b62831905fda6`.

Keep the library's **Import** entry point. Convert it to a Mantine menu with **Local file** and **GitHub folder**. Local file opens the same hidden JSON picker, calls the same legacy or bundle import path, clears the picker value, and opens the resulting workflow. Cancelling the picker saves nothing. Repeated selection of the same file still works.

GitHub folder opens a dialog titled **Import from GitHub**. Use the shared Modal behavior and theme. A desktop width near the existing 780-pixel publication dialog gives descriptions and filenames room. Constrain it to the viewport on smaller screens.

### Source and discovery

Use a labeled TextInput, **GitHub folder URL**, followed by **Load workflows**. Include one useful field description: "Public repository folders only. Includes direct files." Use a representative folder URL as the placeholder. Enter in the URL field runs discovery, never import. Avoid a form submission path that can activate Import accidentally.

Show **Loading workflows...** in a polite status region. Leave the URL editable and offer **Cancel loading**. Cancel loading stops or disregards the active request, clears its result and selection, and keeps the dialog open. Closing the dialog also discards discovery. Reopening begins with no previous results or selection.

Treat the source text, resolved commit, preview identity, selection, and request generation as one coherent state. Every source edit immediately clears results, diagnostics, selection, and import eligibility. Cancel or abort the old request when possible. Late success, error, or finalization from an older request must not replace newer results or clear a newer loading indicator. Retry loads the current URL with a new request identity.

After loading, display the repository, resolved ref and commit, and folder above the results. Long identities wrap. This identifies the reviewed source even for a branch link. A branch must not silently move between preview and import. If the implementation cannot retain the preview's validated bytes or pinned identity, it must require a fresh preview rather than importing unseen changed content.

### Selection and information hierarchy

Use vertically stacked result rows, not a second library card grid. Each row has a Mantine checkbox, root name, plain-text description when present, source filename, and a compact dependency summary. Keep the name visually strongest, then description, then source and dependencies. Omit empty descriptions rather than inventing filler.

The checkbox's accessible label identifies the root and source file. Connect the description and dependency summary with `aria-describedby`. Render names and descriptions as text. Do not interpret HTML or Markdown, and do not use descriptions as markup or URLs.

Sort rows by source filename. One portable bundle has one checkbox for its root. Included children, library dependencies, and saved prompts are not separate choices. Show counts with explicit terms, such as "Includes 1 child workflow and 1 saved prompt." Offer an inline Details disclosure listing dependency names, IDs, ownership, and included published versions or referenced pins. For a legacy row, say "Creates a new workflow" to explain repeat imports. For a bundle, identify the portable format and its included root versions. Keep stable IDs in Details rather than competing with names.

Show a selected-root count near the footer. Import reads **Import 3 workflows** for three selected roots. The label counts roots, not child dependencies. Disable Import for zero selections, during discovery, after a source edit, or while import is pending. Keep a nearby "Select workflows to import" instruction when selection is empty. No row, disclosure, checkbox change, or select-all action can trigger import. A select-all control is unnecessary for the fixture-sized first version.

Report files that cannot be imported separately below valid choices. A compact disclosure, **Files not available for import**, lists filenames and actionable reasons. These are diagnostics, with no selectable checkbox. Unrelated files can be summarized as ignored. Explain unsupported node kinds, invalid JSON, invalid bundle shape, and missing dependency identities without exposing a stack trace. Do not list nested files as discovered choices. Valid file 04 remains a choice because it is valid by itself; selecting it with conflicting data produces an atomic import error.

If there are no valid choices, show "No importable workflows found in this folder." Follow with "Choose another folder. Only direct files are checked." Retain the URL, reload action, and available diagnostics. Keep Import disabled. An empty folder is distinct from a failed request.

### Errors, import, and success

Place malformed or unsupported URL feedback at the URL input. Explain the required public `github.com` folder-link form. A missing folder needs a correction path. A fetch failure or GitHub rejection needs **Retry** and an editable source. Rate-limit feedback reports the service's retry time when supplied, without inventing a countdown. Keep discovery errors inline and readable after focus moves.

Import disables the source, selection controls, Import, and all close or cancel actions. Show **Importing workflows...** in the status region. A short pending note explains "Import has started. Wait for the result." Escape must not pretend to cancel a commit request. The close control must visibly reflect the disabled state, rather than looking active while ignoring clicks. Before Import, closing or cancelling remains available and commits nothing.

On validation or conflict failure, keep the dialog, source, and selection. Show an alert near the action area: "Nothing imported", followed by the relevant filename, workflow or prompt identity, and reason. Preserve all existing local data. A conflict between selected files directs the person to deselect one. A conflict with existing data directs them to inspect that workflow or prompt. Do not offer force, overwrite, or retry semantics that bypass validation. Re-enabling Import always performs fresh validation against current state, including changes since preview.

A lost connection after submitting a mutation is not proof that nothing committed. For uncertain outcomes, explain that the result could not be confirmed and direct the person to inspect the library before retrying. This matters for legacy files, which create new identities on every import. Report "Nothing imported" only when the server establishes rejection and rollback.

On confirmed success, refresh the library and replace results with a success summary in the dialog. Distinguish changed roots and unchanged portable roots. Report included child workflows and prompts without adding them to the root count. Provide links to the resulting roots and **Done**. Do not open an arbitrary root or start it. Focus the success heading and let Done return focus to the library Import button. Import cannot repeat from the success screen without a new explicit discovery and selection.

A refresh failure after a successful commit says the import completed but the view could not refresh. It must not report rollback or invite blind legacy reimport.

### Focus, accessibility, and layout

Use Mantine Menu and Modal keyboard behavior. Focus the URL input when the GitHub dialog opens. Trap focus inside the dialog and restore focus to Import on dismissal. Use visible focus outlines. Checkboxes respond to Space, buttons respond to Enter, and Details uses a real disclosure control. Checkbox and Details targets must be separate so inspecting dependencies never toggles selection.

Announce discovery completion and selected counts through a concise polite status region. Announce errors through an alert. Keep asynchronous discovery from stealing focus if the person is editing the source or using another control. Move focus deliberately only on dialog open, confirmed success, or explicit validation that needs field correction.

At a narrow width around 390 pixels, stack the source input and load action, wrap filenames and IDs, and stack the footer controls if needed. Keep checkbox labels and dependency disclosures readable. Use a bounded scrollable dialog body while preserving access to its title and action area. Do not depend on hover, color alone, truncated text, or a wide table. Inspect the surrounding library header too: its current horizontal flex layout can crowd the entry point on narrow screens. Make only the layout adjustments needed for the actual journey.

### Retrieval bounds and failure policy

Use at most 16 candidate ref probes, 200 direct directory entries, and 100 candidate JSON files. Limit each JSON file to 1 MiB and decoded JSON bytes across the discovery to 8 MiB. Bound the directory response to 2 MiB and commit metadata responses to 1 MiB. Use at most four simultaneous file requests, a 15-second request timeout, and a 60-second deadline for the full discovery. Check byte limits while reading bodies, not only after parsing or from Content-Length. Abort remaining retrieval when the operation deadline or aggregate limit is exceeded. Show an explicit smaller-folder recovery for entry, candidate, or aggregate limits; do not present an incomplete scan as complete. Oversized individual files can be nonselectable diagnostics while other files remain available.

Use public unauthenticated REST reads. Prefer fixed GitHub API URLs and pinned content requests rather than arbitrary download URLs. Recheck allowed destinations before following a redirect or reject unsupported redirects with useful feedback. Do not add credentials. Rate-limit errors include supplied Retry-After or reset metadata, and expose Retry without automatic retry loops. ## Implementation notes

The runtime stages the complete merged selection in an isolated in-memory Store with the existing portable importer and legacy Engine.create. This avoids duplicating conflict, prompt-history and creation rules. Application state stays unchanged until staging succeeds; one outer transaction protects reads and writes. The native tests include frozen public fixture copies at commit 4c43bd7e54651dd9f8356456d647fb86f504252c, both script languages without execution, current-state conflicts, storage rollback and local picker behavior. The shared API names and bounds match docs/github-import.md. No CLI or MCP remote operations were added.

File retrieval uses fixed pinned raw.githubusercontent.com URLs rather than one REST request per file. Metadata still uses the GitHub REST API. This reduces unauthenticated API rate-limit pressure while retaining redirect rejection, byte limits and immutable source identity. It is a routine engineering adjustment to the recommended retrieval mechanism.
