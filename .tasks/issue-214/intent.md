## Source Request
Issue #214: Code-split UI routes with React.lazy to reduce initial bundle size

## Problem Statement
In `packages/ui/src/routes/index.tsx`, all feature route components (`WorkflowLibrary`, `WorkflowEditor`, `RunList`, `RunInspector`, `Harnesses`, `PromptLibrary`, `PromptEditor`, `VariableLibrary`, `Variables`) are statically imported. Because these components pull in complex dependency subtrees—such as React Flow (`@xyflow/react`), custom node inspectors, Monaco/code editors, and graph layout utilities—Vite compiles all routes into a single monolithic bundle chunk (`index-*.js`) of ~937 kB minified (>1.2 MB uncompressed). This triggers a Vite warning about chunks exceeding 500 kB and increases initial page load times for users who may only visit a subset of routes.

## Desired Outcome
- Major route components are dynamically imported using `React.lazy()` so that their code chunks are downloaded only when navigating to their respective routes.
- The initial entry chunk size generated by Vite is reduced well below the 500 kB warning threshold.
- Route boundaries provide an appropriate `Suspense` fallback (e.g., using existing loading/skeleton components) to prevent layout shifts and flickering while maintaining a seamless user experience.
- Existing UI tests and workflows continue to pass without regression.

## Affected Users and Systems
- End users interacting with the Interlock web UI: will experience faster initial load times and smaller download footprints.
- Web UI bundle artifacts (`packages/ui` dist output).

## Scope
### In Scope
- Refactoring `packages/ui/src/routes/index.tsx` to dynamically import route components via `React.lazy()`.
- Wrapping route components with `<Suspense fallback={...}>` using appropriate loading skeletons or spinners.
- Verifying code chunking and bundle size reduction during `pnpm build`.
- Adding a patch changeset for `@type_of/interlock`.
- Ensuring all existing UI and repo tests pass.

### Out of Scope
- Architectural changes to the feature components themselves.
- Altering server APIs, MCP definitions, or execution runtime.

## Constraints

- Preserve existing route navigation behavior, query parameter persistence, and dirty state callbacks.
- Maintain draft-save validation separation and UI purposefulness rules.
- Only patch bump `@type_of/interlock` for non-breaking changes.
