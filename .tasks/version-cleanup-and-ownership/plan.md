# Implement and verify version cleanup

Follow [intent.md](intent.md) for scope and [spec.md](spec.md) for behavior. Stable acceptance criteria in the specification own the requirements.

## Approach and sequence

1. Add shared cleanup input contracts in core. Add storage operations for retained version listing and deletion identity records. Use a stable hash of the canonical definition so equivalent object key ordering does not change identity. Keep deleted definitions out of those records. No schema migration is needed for the document collections. Covers AC1, AC5, AC6, and AC7.
2. Add a runtime cleanup module that computes selected definitions, exact referencing nodes, transitive active-run dependencies, and historical impact. Confirm an impact fingerprint inside one storage transaction before deleting definitions and recording identities. Keep Engine sequencing in runtime. Covers AC1 through AC5 and AC11.
3. Update export/import for retained lists and optional deletion identity records. Use a new bundle format only when those records are present, retaining existing formats otherwise. Preserve local deletion decisions on ordinary import, report skips, and add explicit original-definition restoration. Validate all retained imported dependencies, including imports that skip deleted records. Covers AC6 and AC7.
4. Make full inspection and continuation briefings tolerate deliberately missing definitions. Reject starts and retries before writes when required definitions are missing. Keep execution data and child ancestry unchanged. Adapt existing history UI to the specified missing-definition state. Covers AC8 through AC10.
5. Expose preview and deletion through the shared router and MCP. Add restoration to shared import, MCP import, and CLI import so existing transfer paths stay consistent. Review affected tool descriptions and server instructions. Update README, architecture, limits, agent usage, CLI help, and the glossary if its version definition needs clarification. Add a pending patch changeset. Covers AC11 and AC12.
6. Commit the verified candidate. Use an isolated reviewer without inherited implementation history as required by SDLC version 4. Deliver the cleanup PR after review and record the exact reviewed commit. Ownership changes remain a separate follow-up run and PR.

## Independent review checks

The fresh reviewer inspects the complete diff from the original base commit recorded in intent.md. Inspect saved builder proof against each criterion and the exact candidate commit. Independently exercise at least the destructive boundary: reject a stale preview and a changed-definition restoration with unchanged protected state, then run valid cleanup and restore controls. Check transitive active-run protection and the missing-history response at a second boundary if the diff or builder evidence raises a concern. Review package boundaries, backward compatibility, patch changeset, affected docs, and HTTP/stdio tool discovery.

The reviewer submits pass only for verified criteria, records concrete findings otherwise, and never claims existing context is fresh. Delivery verifies HEAD still equals the reviewed commit. Do not merge or publish.

## Risks and facts

Verified repository facts: published definitions are document records keyed by workflow ID and version; operations use synchronous storage transactions. Export and import currently assume consecutive versions. Full inspection throws for a missing definition, continuation dereferences Batch definitions, and the history UI assumes a graph is present. The latest published version is the publication counter, and preserving it avoids renumbering.

Identity records must use parsed definition semantics consistently with import normalization. New transfer metadata must preserve old bundle behavior when no cleanup occurred. Conservative active dependency checks may intentionally defer cleanup until a run finishes. Historical records alone do not authorize a retry after cleanup.

There are no unresolved plan decisions. API naming, hash implementation, and test fixtures are ordinary implementation choices within the accepted specification.

## Implementation findings and verification

The browser check found a zero-width graph column at 390 pixels because the existing details panel had a fixed width. The missing-definition inspector now stacks history and details at narrow widths and uses a compact explanation in place of the graph. This change applies only when its definition is unavailable. The spec's UI proposal records that clarification.

Selected-file import combines portable bundles before importing. That path also needed to preserve format-3 deletion identities and reject contradictory selected backups. It reports skipped versions and keeps the selected-set transaction boundary. Coverage includes both orders of a conflicting cleaned export and pre-cleanup backup.

Builder proof is saved outside the checkout in `/tmp/interlock-version-cleanup-proof/`. Tests cover AC1 through AC9 and AC11 through AC12 in `versionCleanup.test.ts`, transport tests, and existing regression suites. UI tests and the actual browser journey cover AC10. The browser journey selects a completed Batch execution, expands retained events, follows Batch item and Workflow child links, inspects failed-run inputs with retry absent, checks the explanation at 390 pixels, and verifies a retained v2 graph as a control. Desktop and narrow screenshots and fixture run IDs are saved with the proof. No browser errors were observed. The user's database was not used.

Affected guidance checked: README, architecture, limits, prompt bundle guidance, version-cleanup guide, portable import/deletion guidance, CLI import help, and MCP server instructions and affected tool schemas/descriptions. The MCP review covers version listing, cleanup preview/deletion, transfer and restoration, creation/publication/preflight, start, inspection, briefings/results, retry, and workflow deletion. HTTP and stdio discovery tests exercise the new operations and CLI restoration. This is an audit of affected flows, not the complete MCP tool set.
