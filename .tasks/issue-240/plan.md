## Verified repository facts and risks

WorkflowTriggers currently assumes schedules, transfer format 6 carries schedules and variables, and ExternalInputs is a two-phase submit/accept contract. The server uses a host/origin-checked Hono app bound to 127.0.0.1. Generic document storage supports additive collections, and trigger history uses indexed queries. Primary risks are weakening existing local routes, treating unsigned identity/time as trusted, delivering a stale event to a later node visit, duplicate effects after trimming logs and schedule regressions. Each has the direct positive/negative controls above. No product decision remains open.

## MCP impact for delivery

No MCP tools are added. Existing trigger tools accept both schedule and webhook configurations; export/import adds format 7 and variable inspection adds paged trigger dependencies. Discovery retains 61 tools. Required signing and action contracts appear in management and portable import schemas; action variants are flattened to avoid repeated binding/external-task schemas. The transport discovery ceiling increases from 285,000 to 300,000 bytes for those contracts, with final measured size in the transport log. Server instructions remain below 10,000 bytes. Trigger lists omit payload templates and authentication/action detail; inspection fetches configuration and at most 20 delivery rows by default, 100 maximum, with 200 retained outcome-only rows. Logs exclude bodies, headers, signatures and values. Durable replay receipts remain local and separate from bounded logs. The final PR should carry this explanation in the template's MCP impact section.
