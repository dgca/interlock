# Interlock v2 component inventory

The initial inventory reviewed all 93 TSX files and 43 stylesheets under `packages/ui/src`, plus the shared theme. Source ownership links and [the source manifest](ui-source-inventory.json) are refreshed during implementation as modules move or appear. JSX/import analysis was followed by owner and composition review. This is not a runtime interaction or accessibility audit.

The [Pen file](../interlock-design-directions.pen) is the visual target. The application uses the Grid design-system foundation and migrated screen compositions. Reusable Pen masters do not imply new React wrappers. Import visual controls through `packages/ui/src/design-system`, re-export Mantine controls where their existing interfaces fit, and preserve shared behavior and feature-specific editors. Context-independent components belong in the design system; application compositions remain in `components`.

## Coverage and decisions

- Standard controls are 40px; segmented interiors are 32px with 4px track padding. Attached tabs are 44px. The flat editor control stack stays 32px.
- Existing default appearances are extracted from approved screens. Newly drawn hover, pressed, busy, validation, or selection examples are proposals until reviewed.
- Preserve native/Mantine semantics, keyboard behavior, validation, focus return, and local draft behavior. A static Pen specimen cannot verify these.
- Native `<details>`, file input, datetime-local, and title attributes are real current patterns. No custom calendar, rich-text editor, slider, or tooltip library is assumed.
- Active Runs offers Board and List presentations with bounded attention and completed-run previews. Cards use actual execution metadata rather than an inferred progress ratio.
- Specialist editor and consequential-action compositions stay inventory-only where an accurate complete v2 design has not been made. Do not equate a base field or modal specimen with coverage of an entire workflow.

## Pen coverage

The library contains 57 cataloged UI masters across 12 boards, alongside the approved overview and logo. [The library guide](design-system.md) explains component reuse and migration coverage. [The inventory JSON](component-inventory.json) records master IDs, coverage status, and source ownership for each family. Required variants below describe the full need, not a claim that every state is drawn. New specimens remain proposals.

## Migration boundaries

Existing shared modules include Button, Badge, PageLayout, Modal/ModalLayout, EmptyState, LoadingSkeleton, ListTable, WorkflowCards, SchemaInput, ContractEditor, JsonEditor, CodeEditor, and Sidebar. Their responsibilities should survive the visual migration.

Candidate shared compositions are a consistent form-field frame, padded action group, disclosure row, ordered-reference row, and key/value row. Shared visual structure does not establish identical domain behavior: tag uniqueness, environment binding, HTTP headers, prompt revision order, and secret replacement keep their separate contracts.

The inventory JSON records Pen master IDs and whether a family is extracted, proposed, partial, or inventory-only. The source manifest lists every scanned file, exports, imported Mantine controls, and JSX elements so unrepresented features remain discoverable.
