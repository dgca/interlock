An owned helper workflow without its own agent now runs on its caller's managed harness instead of waiting for a connected agent. When a workflow invokes a child workflow it owns through a Workflow step, and the child sets no Default Agent executor, the child's Agent steps use the caller's published harness for that run, so selecting a harness once on the SDLC workflow is enough for Plan review and Change review. Only the harness is inherited: the child's own permissions, model, effort, permission policy and Agent presets still apply, and node executors, including explicit connected-agent choices, still win. The child captures the harness when it starts, so retries and restarts keep it after later edits; child runs started before upgrading keep waiting for a connected agent. Library workflows, Start and continue children and comparison trials are unchanged. Workflow settings of an owned helper show the owner's agent, execution details show the harness as from the calling workflow, and assignment data reports `executorSource: "caller"`.
