Agent work you can run twice.
Draw the procedure once, then replay it on the record.

Interlock is a local workflow editor and engine for AI agents. You draw the procedure as a graph. Interlock runs the HTTP, JavaScript and Bash steps itself, hands each judgment call to the agent you already use over MCP, checks every result against a contract, and keeps the whole run in SQLite where you can inspect it. Try it below: you are the agent.

  1. Step 1 · the engine goes firstCode steps run. One waits.

    Fetch, Script and Condition run in the engine in under a second. The run pauses only where judgment is needed.

  2. Step 2 · the assignment is the contractInput, prompt, policy, schema.

    The details panel shows exactly what the agent receives, including the output schema its answer must pass.

  3. Step 3 · an executor claims itAn expiring, renewable lease.

    The claim carries a token and a 300-second lease. If the agent goes quiet, the work becomes available again.

  4. Step 4 · checked, then recordedEvery execution, kept.

    A wrong answer is rejected with the reason and the claim stays open. Each step keeps its input and output on the run.

Steps are paced so you can watch them. The Script is the starter workflow's own JavaScript and errors use Interlock's contract wording; no Interlock engine runs on this page.

1.0

Write the procedure down once. Every run follows the same graph.

Most agent procedures live in a chat log: the steps, their order, and the checks between them are only as repeatable as the last prompt. In Interlock a workflow is a graph with one entry, typed steps, and named exits. The steps that need no judgment run as code. The agent gets only the steps that need it.

2.0

Every step says what it accepts. Every result gets checked.

Workflows and nodes carry input and output contracts: JSON Schema, edited through a field editor or pasted from example JSON. The engine validates real values at execution time. An agent that returns the wrong shape is told exactly what is missing, and its claim stays open so it can correct the answer.

3.0

Interlock never calls a model. Your agent does the thinking.

The engine serves Streamable HTTP MCP at 127.0.0.1:4310/mcp from the same process as the UI. Point Codex, Claude Code, OpenCode, or any MCP client at it, and the agent can find a workflow, start a run, claim assignments and submit results. The CLI drives the same API. Your harness keeps its own tools, approvals and model.

    5.0

    Drafts change. Published versions never do.

    Edit freely: drafts save incomplete, and Undo covers the last 50 editor actions. Review & publish compares the draft, unsaved edits included, with the latest published version before anything ships. Each run is pinned to one immutable version, so editing a workflow never changes a run already in flight. Edit the prompt below and publish it.

    • PinnedWorkflow nodes pin a published version of the workflow they call. Later publications do not move existing pins.

    6.0

    Two commands. Then ask your agent.

    The npm package includes the engine, the UI, the CLI and the MCP tools. No separate build, no account, no API key. Workflows and runs live in ~/.interlock/interlock.db and survive restarts. 

    # node 24.13 or later, macOS or Linux
$ npm install -g @type_of/interlock
$ interlock
Interlock is running at http://127.0.0.1:4310

# connect your harness, e.g. Claude Code
$ claude mcp add --transport http --scope user \
    interlock http://127.0.0.1:4310/mcp

# or try it without installing
$ npx -y @type_of/interlock@latest

    know before you run it

    • LocalSingle user, on loopback, with no authentication. Do not expose it through a public tunnel.
    • ScriptsJavaScript and Bash steps run with your account's files, environment and network. They are not sandboxed; review imported workflows first.
    • AgentsInterlock does not launch agent sessions or call model APIs. Agent steps need a connected executor or manual completion.
    • ScopeNo recurring schedules, multi-user access, or arbitrary parallel joins yet. See current scope.
